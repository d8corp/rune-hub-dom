# Quick Start

This guide will take you from an empty directory to a running application, help you understand the core building blocks, and prepare your project for production.

### Prerequisites

- **Node.js** 22 or higher
- **Package manager**: npm, yarn, or pnpm
- **Browser**: Any modern browser supporting ES6+

## Getting Started
---
The fastest way to create an application is the Rundom CLI:

```shell
//! Rundom CLI
npx rundom init my-app
cd my-app
npm start
```

> `my-app` is the working folder. Run `npx rundom init` without an argument to create the app in the current folder.

The CLI creates a minimal project with an entry point, TypeScript configuration, and npm scripts for development and production builds.

```
//! Rundom CLI structure
my-app/
├── index.html         // HTML shell
├── src/
│   ├── index.ts       // Application entry point
│   └── tsconfig.json  // TypeScript configuration
└── package.json
```

Feel free to use any preferred tooling. The same app can be scaffolded with [Vite](/) or [InnetJS](https://www.npmjs.com/package/innetjs):

```shell
//! Vite
npm create vite@latest my-app -- --template rundom
//! InnetJS
npx innetjs init my-app --template rundom
```

> The `--template rundom` flag creates a `rundom` frontend template, and `my-app` is the working folder.

The Vite and InnetJS templates include component examples, configured routing, a development server with TypeScript + JSX setup, and an optimized build pipeline.

```
//! Vite structure
my-app/
├── public/
├── index.html         // HTML shell
├── src/
│   └── index.tsx      // Application entry point
├── tsconfig.json      // TypeScript and JSX configuration
└── package.json
//! Innet structure
my-app/
├── public/
│   └── index.html     // HTML shell
├── src/
│   └── index.tsx      // Application entry point
├── tsconfig.json      // TypeScript and JSX configuration
└── package.json
```

## Rundom CLI
---
The `rundom` package ships with a CLI that wraps Vite. Run it with `npx rundom` or use the npm scripts generated by `init`:

| Command | Description |
| --- | --- |
| `npx rundom init [app-path]` | Creates a new app and installs its dependencies. Defaults to the current folder. |
| `npx rundom start [app-path]` | Starts the development server and updates the app when project files change. |
| `npx rundom build [app-path]` | Builds an optimized production bundle into the `build` folder. |
| `npx rundom preview [app-path]` | Serves the existing `build` folder on port `4173` (override with `PORT`). |

For convenience, the generated `package.json` contains these scripts:

```json
//! package.json
{
  "scripts": {
    "start": "rundom start",
    "build": "rundom build",
    "preview": "rundom preview"
  }
}
```

So `npm start`, `npm run build`, and `npm run preview` are equivalent to the corresponding `npx rundom` commands.

Let's look under the hood of your new project. 
The following steps break down the generated files, explain how they work together, and show you how to run and build your app.

## The Entry Point
---

Open `src/index.ts` in a project created by the Rundom CLI, or `src/index.tsx` in the Vite and InnetJS templates. This is where your application comes to life:

```tsx
//! Vite / InnetJS
import { rundom } from 'rundom'

function App () {
  return (
    <div>
      <h1>Hello, Innet!</h1>
      <p>Your first reactive application</p>
    </div>
  )
}

rundom(<App />)
//! Rundom CLI
import { rundom } from 'rundom'

rundom('Hello World!')
```

The `rundom()` function takes a renderable value, such as a JSX component or a string, and mounts it to the DOM.

## HTML Shell
---

Next, look at `index.html`.
This is the shell that hosts your app:

```html
//! Rundom CLI
<!doctype html>
<html lang="en">
  <head>
    <meta charset="UTF-8">
    <meta name="viewport" content="width=device-width, initial-scale=1.0">
    <title>Rundom</title>
    <script type="module" defer src="src/index.ts"></script>
  </head>
  <body>
    <!-- rundom automatically injects your app here -->
  </body>
</html>
//! Vite
<!doctype html>
<html lang="en">
  <head>
    <meta charset="UTF-8">
    <meta name="viewport" content="width=device-width, initial-scale=1.0">
    <title>Innet App</title>
    <script type="module" defer src="/src/index.tsx"></script>
  </head>
  <body>
    <!-- rundom automatically injects your app here -->
  </body>
</html>
//! InnetJS
<!doctype html>
<html lang="en">
  <head>
    <meta charset="UTF-8">
    <meta name="viewport" content="width=device-width, initial-scale=1.0">
    <title>Innet App</title>
    <script type="module" defer src="index.js"></script>
  </head>
  <body>
    <!-- rundom automatically injects your app here -->
  </body>
</html>
```

By default, `rundom` attaches your application directly to `document.body`.
If you prefer to mount your app inside a specific wrapper (like `<div id="root">`), you can easily do so using the built-in [Portal](/portal) component.

## TypeScript & JSX
---

To ensure TypeScript understands JSX syntax of `rundom`, the CLI configures `tsconfig.json` like this. The Rundom CLI writes it to `src/tsconfig.json`, while the Vite and InnetJS templates place it in the project root:

```json
//! tsconfig.json
{
  "compilerOptions": {
    "rootDir": "src",
    "target": "ES2018",
    "lib": [ "dom", "dom.iterable", "esnext" ],
    "skipLibCheck": true,
    "module": "ESNext",
    "moduleResolution": "bundler",
    "strict": true,
    "jsx": "react-jsx",
    "jsxImportSource": "rundom"
  },
  "include": [ "src" ]
}
```

> Make sure you add `"jsx": "react-jsx"` and `"jsxImportSource": "rundom"` to use JSX.

## Development Server
---

If you haven't already, fire up the development server:

```shell
//! Terminal
npm start
```

The `npm start` script runs `rundom start`. The Rundom CLI (like the Vite or InnetJS CLIs) acts as your bundler and dev server, providing TypeScript compilation, JSX transformation, and lightning-fast rebuilds.

## Build for Production
---

Once you are happy with your app and ready to deploy, you need to create an optimized production bundle:

```shell
//! Terminal
npm run build
```

The `npm run build` script runs `rundom build`. It compiles your application, applies minification, tree-shaking, and other optimizations.
The final static files are written to a `build` folder by default.
Because `rundom` ships a fully static bundle, there is no server-side runtime required — you can deploy the `build` folder to any static hosting provider (Netlify, Vercel, GitHub Pages, AWS S3, etc.).

You can check the production build locally with:

```shell
//! Terminal
npm run preview
```

`rundom preview` serves the `build` folder on port `4173` by default.
